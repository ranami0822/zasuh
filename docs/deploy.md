# Zasuh のデプロイ手順（初回と、その後）

状態: **初回のデプロイは済み**（2026-11-17）。手順は、`docs/mvp-design.md` の12・13章を前提にする。

実際にやったこと（2026-11-17）: 無料プランの D1 の上限（10個）に達していたので、使っていなかった `cram-book-db`（空）を、ユーザーの指示で消して（先に書き出した。中身は空）、`zasuh` を作った。D1 の ID は `wrangler.jsonc` に入っている。`ADMIN_TOKEN` は、乱数で作って、シークレットに入れた（ユーザーにだけ伝えた。リポジトリには入っていない）。公開先は `https://review.anami.party`（2026-11-18 から。`anami.party` のゾーンに、カスタムドメインとして足した）。

デプロイ後の確認の結果: トップが開く、`/admin` がログインなしで `/admin/login` に飛ぶ、ログインなしの POST が 403、セキュリティのヘッダが付く、合言葉でログインできる、作品の登録、投稿、**本番の Workers AI が、投稿の直後にレビューを読んで、向きのタグが付いた**。確認のために作ったデータは、すべて消した（`tags` と `question_sets` は、読み取りのときに自動で作られる記録なので、残してある）。

アカウントの状況: workers.dev のサブドメインは `crami`。同じアカウントに、ほかの Worker と D1 が複数ある（ほかのプロジェクトのものなので、触らない）。

## 初回（この順番で。済み）

1. **D1 を作る**: `npx wrangler d1 create zasuh`。出てきた `database_id` を、`wrangler.jsonc` の `database_id`（いまは `0000…` の仮の値）に書いて、コミットする。
2. **テーブルを作る**: `npm run db:migrate:remote`（`migrations/0001_init.sql` を適用する。本番では、このファイルを、あとから書き換えない。変えるときは `0002_…sql` を足す）。
3. **合言葉を入れる**: `npx wrangler secret put ADMIN_TOKEN`。**長い乱数**にする（例: `openssl rand -base64 32`）。管理画面のログインと、送信元のハッシュの鍵に使う。あとから変えると、全員の管理のログインが切れ、送信元のハッシュも変わる（上限の数え直しになるだけ）。
4. **デプロイ**: `npm run deploy`（ビルドして `wrangler deploy`）。
5. **確かめる**（下の「デプロイ後の確認」）。

- [ ] `npm test`、`npm run check` が通る
- [ ] ローカルで `npm run dev:worker` を動かし、`npm run e2e` が通る（空のデータベースで）
- [ ] `git status` が空（コミット済み）
- [ ] `wrangler.jsonc` の `database_id` が、本番の ID になっている
- [ ] `ADMIN_TOKEN` が、本番に入っている（`npx wrangler secret list`）
- [ ] 質問の文面（タグ）を変えたときは、**版を上げて**新しい定義として足した（上げないと、読み取りがエラーで止まる）
- [ ] マイグレーションを足したときは、ローカルで先に適用して確かめた

## デプロイ後の確認

- [ ] `/` が開く（作品がなければ、「まだ作品がありません」）
- [ ] `/admin` が、ログインなしで `/admin/login` に飛ぶ。ログインなしの POST（`/admin?/create`）が 403 になる
- [ ] `/admin/login` で、`ADMIN_TOKEN` で入れる
- [ ] 作品を1つ登録して、追加のタグを選べる
- [ ] 別の端末（または別のブラウザ）から、レビューを1件投稿して、**1分以内にタグと向きが付く**（Workers AI のバインディングと、投稿直後の読み取り）
- [ ] 読み取りに失敗したら、毎分の定期実行が拾う。ダッシュボードのログに `sweep` が出る
- [ ] 応答ヘッダに、`x-frame-options`、`x-content-type-options` がある
- [ ] 試しに投稿したレビューを、管理画面から削除する

## 注意（無料枠、費用）

- Workers AI: 1日 10,000 neurons まで無料。分野のタグだけなら、1日に約 1,270 件。超えると、読み取りが失敗する（429）が、レビューは保存され、枠が戻ると、定期実行が読み直す。
- **Workers の無料プランは、1回の呼び出しの CPU 時間が 10 ms。** 投稿時の「文面がほぼ同じか」の比較（最大500件）が、レビューの多い作品で超えるおそれがある。超えたら、有料プラン（月 $5）にするか、比べる件数を減らす（`src/lib/server/text.ts` の `DUPLICATE_SCAN_LIMIT`）。
- 定期実行は毎分。D1 の読み取りは、無料枠（1日 500万行）に十分収まる見込み。

## 元に戻す

- **コードだけ戻す**: `npx wrangler rollback`（直前の版に戻る）。D1 のデータは、そのまま。
- **スキーマを戻す**: D1 のマイグレーションは、戻せない。変更は、足すだけ（古い列を残す）にして、戻す必要が出ないようにする。D1 は、Time Travel（30日）で、特定の時点のデータベースに戻せる（`npx wrangler d1 time-travel restore`）。
- 戻す目安: 投稿か読み取りが、続けて失敗する、管理画面に、ログインなしで入れる、データが消える。

## ドメイン（2026-11-18）

- **`review.anami.party`**（ユーザーが選んだ。私は、サービス名の `zasuh.anami.party` を勧めたが、`review` を選んだ）。`wrangler.jsonc` の `routes` に、カスタムドメインとして入れてある。DNS の記録と証明書は、Cloudflare が自動で作った。
- 旧 URL（`zasuh.crami.workers.dev`）は、`workers_dev: false` で無効にした（開くと 404）。転送は、していない。最初に共有した URL は、開けなくなる。
- **passkey を入れるときの RP ID は、`review.anami.party` にする**（`anami.party` 全体にはしない。ほかのサブドメインのサービスと、パスキーを共有しないため）。一度決めたら、変えない（変えると、登録したパスキーが、すべて使えなくなる）。`review` は機能を表す一般的な名前なので、あとで同じ名前を、別のものに使いたくならないようにする。
- Cookie は、ドメインを指定していないので、`review.anami.party` だけに送られる（ほかのサブドメインには、送られない）。
- このトークンでは、ゾーンの DNS の記録は、読めない（認証エラー）。カスタムドメインの追加は、同名の記録があれば、上書きせずに失敗する。

## まだ決まっていないこと

- 管理画面を、Cloudflare Access で守るか（合言葉だけでも、長い乱数なら足りるが、複数人になったら変える）。
- 本番のデータの定期的な書き出し（バックアップ）。D1 の Time Travel は 30 日。
