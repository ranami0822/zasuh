状態: 方向と、ライトの色は本人の決定（2026-11-15の提案パレット）。ライトとダークの色は、本人の決定（ダークの文字色などは私の案）。見た目の案は `pnn/design/preview-b.html`（ライト）と `preview-dark.html`（ダーク）。

## 1. 方向（決定、2026-11-15）【今回】

- 「乳首」。バカなこと。部品は乳首の隠喩で、ユーザーが触ることは、アプリの乳首をいじること。
- **色は、乳首そのもの**（肌、輪、赤みのカード）。**ピンクは入れない**（当初の「ピンクがドミナント」は、この提案パレットで置き換わった。ピンクがないこと自体が、本人の意図）。鮮やかなピンクのアクセントは、コンセプトに合わないと判断して見送り（私の意見。本人も迷っていた）。
- ほかの色は灰色のベース（少し前の Apple HIG の灰色）。アクセントは**ミント**（意図的な変更。当初のアーモンドグリーンから）。
- 面を中心にする。線は使わない。グラデーション、粒状感（grain）、色つきの影は、場合に応じて使う。
- 説明しない。感性デザイン。
- 将来（今ではない）: 水色（ミント）の細かいマスクで、下着の模様を表現する。

### 3.1 ダーク（決定、2026-11-15。ライトは変えない）

方向: 暗い肌色（深い茶）。冷たい黒や青みの灰色にせず、肌の温度を残す（本人の「人外になってはいけない」を守るため）。暗い部屋で長く読み書きすることを考えて、文字は純白でなく暖かいクリーム色にする。「暗い肌色」は色の連想で、人種を示す名づけにはしない。

経緯: 背景は本人が承認（`#1F1512`）。面は、暗い案では「乳首」にならないと判断され、明るさと赤みを上げた3案から⑤の茶を選んだ。そのあと、本人が**実際の乳首から取った色**（`#6F4332` `#9E6552` `#AE735C` `#B9826C` `#CC9177`。`#CC9177` は2回挙がっていた）を示し、**ダークだけ**をそれに合わせることに決めた。実測の色相は 15〜18°、彩度は 32〜45% で、⑤とほぼ同じ方向。

## 4. 確認したこと

- UnifontEX（`@fontsource/unifontex` 5.3.0、OFL-1.1）は、1ファイルで日本語（ひらがな、カタカナ、漢字）を描画できた。Chromium で、16px・32px・48px のとき、ドットがくっきり出ることを画面で確認した（`pnn/design/preview.html`）。
- 元の woff2 は約 2 MB の1ファイル。`pnn/scripts/build-font.py` で、6つの塊へ分けた（`pnn/fonts/`）。`unicode-range` で、ページに出た文字が入る塊だけを読み込む。
  - `base`（英数字、かな、日本語の記号、全角形）13 KB
  - `kanji1`（JIS 第1水準の漢字）139 KB
  - `kanji2`（JIS X 0208 の残りの漢字）約 175 KB
  - `symbols`（ラテン・ギリシャ・キリル文字、約物、矢印、図形、ハートなどの記号）約 80 KB。`…` `→` `★` `❤` はここ。JIS X 0208 に入っている記号も、`kanji2` を呼ばないよう、ここに入れた
  - `emoji`（U+1F000〜1FAFF）約 70 KB
  - `rest`（それ以外のすべて、龘など）約 1.4 MB
- 範囲外の文字も、オンラインならドットの見た目で出る（オフラインでキャッシュ前なら、システムのフォントになる）。𠮷（U+20BB7）は UnifontEX に入っていない（システムのフォントになる）。
- **訂正**: 最初に作った塊は、ブラウザの検証（OTS）に拒否され、実際にはシステムのフォントで描画されていた（`post` テーブルを削ったこと、`name` の並びが原因）。当初の確認が、通信（どの塊を取りに行くか）だけで、描画を見ていなかったため。修正後は、`document.fonts` の状態が `loaded` で、警告が出ないことを確認する。
- CDN（jsDelivr）にも同じファイルがあるが、自前で配信する。ブラウザのキャッシュはサイトごとに分かれるので共有の利点がなく、利用者の IP が第三者に渡るため。
- 削ったフォントの全文字の見た目は、確認していない（確認は、塊ごとの読み込みの成否と、画面に出した代表的な文字のみ）。
- **コントラスト（WCAG の比）**: 文字 `#1c1c1e` はピンク `#ff6fa8` の上で 6.6、肌色の上で 14.1。**白い文字はピンクの上で 2.6 で足りない**ので、ピンクの上の文字は暗い灰を使う。**`#7f9c67`（濃いアーモンド）は肌色の上で 2.5 で、文字には使えない**（強調の線や塗りには使える）。

## 5. 注意・未決

- 本文のフォントサイズは 16 の倍数（16 / 32 / 48）が前提と見ている（ピクセルフォントのため。貼り付けられた別のプロジェクトの記録と、16/32/48 でだけ確認した画面からの推測。14px などは未確認）。
- 長い小説を UnifontEX で読めるか（行間、疲れやすさ）は、未確認。小説の場では、別の書体にする選択肢を残す。

- 灰色の使い道: 現状は文字と中立の面だけ。ライトでは肌色が面の大半を占める。灰色をどこまで広げるかは、本人の判断。

## 6. 触ったときの動き（決定、2026-11-15）

試作: `pnn/design/touch/index.html`（押して試せる。3案から、本人が「ンっ…」を選んだ）。

- **押している間**: 素早く沈み（約 0.11 秒）、そのまま約 0.7 秒かけて、さらに深く沈む。面が縮み、影が内側に落ち、色が押下の色になる。沈んだあと、ピクセルの書体に合わせたカクカクした小さな震え（約 0.7px）が出る。
- **離したとき**: 「ぷるっ」と、1.06 → 0.985 → 1.015 → 1 と減衰しながら戻る（約 0.64 秒）。
- **上目遣い**（本人の追加）: 押している間、ボタンの中の文字を縦に下へつぶして（縦 0.74 倍、横 0.88 倍まで）、ボタンの下側に寄せる（下から見上げる）。離すと、ボタンと一緒に跳ねて戻る。本人の言葉は、最初「横につぶして上目遣い」、次に「下につぶせる、下から見つめる感じ」で、後の言い方に合わせて直した（最初の、上へ寄せる案は取り下げ）。ピクセルの書体を非整数倍で縮めるため、わずかににじむ。
- 部品の大きさで強さを変える（ボタン 1、チップ 1.1、ハート 1.3、大きなカード 0.22）。
- **振動**（Android のブラウザのみ。iOS の Safari は不可）: 押すとき 8ms、沈んだときに小さな連続、「ぶる」で切り替え。
- **視差効果を減らす**設定のときは、震えと跳ねをやめ、縮んで色が変わるだけにする。
- 触感は、指で押して確かめる必要がある。ここでは、ブラウザの自動操作で、縮み方と戻り方の数値を確かめただけ。

## 7. 間隔（決定、2026-11-15）

**経緯**: 色、書体、動きは決めていたが、間隔と部品の仕様を決めないまま、アプリを作った。結果、狭い画面で部品が折れ、題が切れ、余白がばらついた（本人の指摘）。以降は、値を `pnn/src/styles/tokens.css` だけに置き、画面と部品は、その変数だけを使う。

- **8px の格子。半分の 4px と 12px を許す**: `--s1` 4 / `--s2` 8 / `--s3` 12 / `--s4` 16 / `--s5` 24 / `--s6` 32 / `--s7` 48 / `--s8` 64。
- **押せる大きさの下限**: `--tap` 44px（高さも幅も）。
- **形**: `--r-pill`（pill）、`--r-card` 24px（面の部品）、`--r-box` 0（ダイアログと、画面の大きな区画）。
- **文字**: 本文 16px、題 32px。行間は、UI 1.5、書く面 2、題 1.4。
- **画面の幅**: `--measure` 680px までで、中央に置く。横の余白 `--gutter` は、狭いほど詰める（360px 未満 12px、通常 16px、640px 以上 24px）。並んだ部品のあいだ `--gap` は、360px 未満で 4px、それ以外 8px。
- **影**: 全方向でずらさない（`--sh-pop` `--sh-card` `--sh-bar` `--sh-dialog`）。
- 値の直書き（px）は、`tokens.css` 以外では、原則しない（1px と 2px の細かい調整は例外）。

## 8. レイアウト

```
┌──────────── 画面（高さ = 見えている高さ。キーボードが出ても追う）────────────┐
│ ┌──────── 列（幅は --measure まで、中央） ────────┐                          │
│ │ 上の列   [状態] ●           [いままで][＋][☾]  │ 折り返さない               │
│ │ 題      （長ければ折り返す。切らない）          │ 32px                      │
│ │ 本文    （残りの高さ。ここだけがスクロールする） │ 16px、行間 2              │
│ └──────────────────────────────────────────────────┘                          │
│ ━━━━ 下の帯（全幅の直角の面。中の列は --measure に揃える）━━━━                 │
│   [↶][↷][見出し][太字]…（横にスクロール。右端をぼかして、続きを示す）          │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 画面全体は、横にスクロールしない。はみ出すのは、下の帯の中の列だけ。
- 上の列は、必ず1行。幅が足りないときは、余白（`--gutter`、`--gap`、`.tight`）を詰めて収める（320px で収まることを確認する）。
- 下の帯は、画面の大きな区画なので直角。中の部品は pill。
- 本文の下には、最後の行が帯に隠れないよう、`--s7` の余白を置く。
