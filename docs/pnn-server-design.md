# pnn 公開の場とログイン 設計（初版）

対象: `pnn/`。エディタ（`docs/pnn-editor-design.md`）の次の段階。要件は `docs/pink-nervous-nipples.md` の 4.1。
範囲外: 小説の場、作業共有スペース、水色のマスクの模様、通報と運営の削除画面（下の「見直す点」）。

## 1. 要件（決定済みのものの再掲）

- 全員匿名が基本。書いた投稿は、仮名で出る。
- 反応: いいね（公開。1人1回）、保存（自分だけ）、返信（双方向。書いた人は非表示にできる）。
- 匿名を外す: 投稿ごとのトグル（いつでも変えられる）。**いいねが閾値（20）を超え、かつトグルが入っている**とき、書いた人のプロフィールが出る。トグルを切れば、匿名に戻る。
- 閾値のいいねは、1人1回。**新しいアカウント（作って3日未満。日数は私の案）のいいねは、閾値に数えない**（いいねの数の表示には含める）。
- プロフィール: 名乗った投稿が並ぶ。フォローできる。フォロワーの数は、本人だけが見られる。
- 限定公開: URL を知っている人だけが見られる（フィードに出ない）。
- ログイン: passkey。

## 2. 全体

```
ブラウザ（PWA。エディタは端末で保存）
   │ 公開・限定にした文書だけ、送る（オフラインなら、あとで送る）
   ▼
Cloudflare Workers（SvelteKit の API）── D1（SQLite）
   └ 秘密の鍵 PNN_SECRET（仮名を作る）
```

## 3. 仮名

- 投稿、返信、いいね、保存には、利用者 ID ではなく **仮名**（`HMAC-SHA256(PNN_SECRET, 利用者ID + ":pnn")` の先頭 16 バイト）を記録する。データベースに、仮名と利用者の対応表は置かない。
- **限界**（正直に書く）: 運営は、秘密の鍵を持っているので、利用者 ID から仮名を計算し直せる。データベースだけが漏れても対応は分からないが、運営からは、完全には見えなくならない。運営からも見えなくするには、端末の中で仮名を作る方式（passkey の PRF など）が要る。見直す点に残す。
- 匿名を外すトグルが入っている投稿だけ、利用者 ID を `reveal_user` に記録する（本人が名乗る意思を示したもの）。トグルを切ると消す。

## 4. データ（D1）

| 表 | 主な列 | 備考 |
| --- | --- | --- |
| `users` | id, created_at, handle（一意。名乗るときに決める）, name, bio | |
| `credentials` | id（passkey の ID）, user_id, public_key, counter | |
| `sessions` | token_hash, user_id, expires_at | cookie には生のトークン。保存はハッシュ |
| `challenges` | id, challenge, expires_at | passkey の一回きりの値 |
| `posts` | id, author（仮名）, doc_id（端末の文書 ID）, title, body, visibility（public/limited）, reveal_user, created_at, updated_at | (author, doc_id) が一意 |
| `likes` | post_id, liker（仮名）, counts（閾値に数えるか）, created_at | (post_id, liker) が一意 |
| `saves` | owner（仮名）, post_id, created_at | 本人だけが見る |
| `replies` | id, post_id, author（仮名）, body, hidden, created_at | |
| `follows` | follower（利用者 ID）, followee（利用者 ID）, created_at | 名乗った人どうしの関係なので、仮名ではない |

## 5. API（`/api`）

| 方法 | パス | 内容 |
| --- | --- | --- |
| POST | `/api/auth/register/options`, `/verify` | passkey を作る（新しいアカウント） |
| POST | `/api/auth/login/options`, `/verify` | passkey で入る |
| POST | `/api/auth/logout` | 出る |
| GET / PATCH | `/api/me` | 自分（handle、名前、紹介。フォロワーの数） |
| PUT / DELETE | `/api/docs/[docId]` | 端末の文書を、公開・限定にする／取り下げる |
| GET | `/api/feed` | 公開の投稿（新しい順。カーソルで続き） |
| GET | `/api/posts/[id]` | 投稿と返信 |
| POST / DELETE | `/api/posts/[id]/like`, `/save` | いいね、保存 |
| POST | `/api/posts/[id]/replies` | 返信 |
| POST | `/api/replies/[id]/hide` | 返信を隠す／戻す（投稿を書いた人だけ） |
| GET | `/api/saves` | 保存した投稿 |
| GET | `/api/users/[handle]` | プロフィールと、名乗った投稿 |
| POST / DELETE | `/api/users/[handle]/follow` | フォロー |

- 書く操作は、ログインが要る。読む操作（フィード、投稿、プロフィール）は、ログインなしでも見られる。
- 入力の上限: 題 200 字、本文 20,000 字、返信 2,000 字（私の案）。

## 6. 本文の表示

- 本文は Markdown のまま保存し、表示のときに、**先に HTML の記号をすべて逃がしてから**、エディタと同じ範囲の記法（見出し、太字、傾き、取り消し、引用、箇条、区切り）だけを HTML にする。外部のライブラリを使わず、許す記法を限ることで、スクリプトの埋め込みを防ぐ。

## 7. エディタとのつながり

- 状態を「限定」か「公開」にすると、ログインしていなければ、passkey を作る（または入る）。
- 公開・限定の文書は、変更のたびに（端末への保存とは別に、2 秒待って）送る。オフラインや失敗のときは、端末に「送る待ち」を残し、オンラインに戻ったときと、開いたときに送り直す。
- 下書きに戻すと、取り下げる（サーバーから消す）。

## 8. トレードオフ

| 決定 | 失うもの |
| --- | --- |
| 仮名は、サーバーの秘密の鍵で作る | 運営からは、対応を計算できる（第3節） |
| 画面は、すべて端末で描く（SSR なし） | 検索エンジンや、リンクの見出し（OGP）に、本文が出ない |
| 本文の表示は、自前の小さな変換 | 表やリンクなど、記法の範囲が狭い |
| 閾値は、表示のたびに数える | 投稿が多くなると遅い（いいねの集計表で直す） |

## 9. 見直す点

1. 仮名を、運営からも見えなくする（端末で作る）。
2. 通報と、運営による削除（いまは、無い）。公開の場として、出す前に要る。
3. 個人情報の検知（以前の提案。採用は未決）。
4. アカウントの復旧（passkey をなくしたとき）。
5. 「新しいアカウント」の日数（3日は私の案）。
