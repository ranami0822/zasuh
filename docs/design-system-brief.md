# デザインシステムの引き継ぎ（別のセッション用）

状態: 2026-11-19。目的: Zasuh のデザインシステムを、作り直す（または、整える）。**この文書は、これまでの決定と、制約と、いまの部品の一覧をまとめたもの。** 経緯の詳細は、`docs/mvp-design.md` の 5、14、17、18 章。

## 1. 製品の見せたいこと（デザインの根拠）

- 人が書いた、**理由つきのレビュー**を、AI が決まった質問で読み取り、**観点ごとの向き（肯定・否定・混在）と件数**にまとめて見せる。**AI は作品を採点しない。点数は付けない。**
- 順位は出す（総合と観点別）。言及が少ないものは、**文字ではなく、見た目（細く、薄く）**で伝える。
- 説明は、なるべく書かない。見た目で伝える。
- 利害関係のあるレビューは、別枠で見せる。AI の読み取りの結果は、公開してよい（隠さない）。AI を、主役のように光らせない（立場に合わない）。
- 対象は、日本語。UI もレビューも、日本語のみ。

## 2. ユーザーが決めたこと（変えない）

- **評価の棒は、赤（否定）と緑（肯定）のままでよい。** 混在は、灰色。色だけで伝えず、割合の文字と記号を添える（色覚への配慮）。
- **角は、レイアウトの面だけ、直角。** 小さな部品（ボタン、タグ、入力欄）は、少し丸める（3〜4px）。ピル形は使わない。
- **灰色の濃淡とモノクロに、差し色を1色だけ載せる**案を検討中（オレンジ、赤、ピンク、シアンの試し）。**差し色は未決**。「シアkし」の意味は、ユーザーに確認する。
- **なんでも独自にすればよいわけではない。** 独自にするのは、色・書体・面の見せ方だけ。フォーム、ボタン、エラーの出し方、ナビゲーションなどの操作は、慣れた形のまま。
- 低コントラストの灰色の文字を、多めに使いたい（ただし、読みやすさの基準は守る。4. 参照）。
- 参考: jdilla.com（灰色の背景、大きく太い書体、白と灰色の差での強調、リンクだけ色つき）。画像は、全体の代表ではない。

## 3. 避けること（「AI が作りがち」な型。出典と照らし合わせは `docs/mvp-design.md` の 17 章）

紫から青のグラデーション、グラデーション文字、黒地に色つきの光（グロー）、蛍光色の差し色で AI を光らせること、大きな数字＋小さな統計＋色の線（ヒーロー指標）、すべてを同じ角丸と同じ影のカードで包むこと、カードの入れ子、同じ余白の繰り返し、ガラス風、片側だけ太い色の縁取り、アイコンの氾濫、バウンスする動き、レイアウトのプロパティ（高さなど）のアニメーション、Inter などの欧文の既定の書体、空の状態に次の行動がないこと。（どれも、ブログやツールの紹介による、コミュニティの合意。測定された研究ではない。）

## 4. 数値の制約

- **コントラスト**: 補足の文字は、地の上で 4.5:1 以上。試し案は、ライト 5:1 以上、ダーク 6:1 以上。**レビューの本文は、高コントラスト。** 画像の参考サイトのような 1.5:1 前後は、使わない。
- **文字の大きさ（日本語）**: 本文 15px / 行間 1.75、レビューの本文は行間 1.9・字間 0.04em、UI の文字 14px、補足は **12px 以上**、入力欄は **16px**（それ未満だと、iPhone の Safari が、フォーカス時に画面を拡大する）。本文は、ベタ組み（`font-kerning: none`）。見出しだけ `palt`、`text-wrap: balance`、`word-break: auto-phrase`（Chrome 119 以降。ほかは無視される）。日本語の太字は、見出しだけ（本文を太くしない）。
- **余白**: 4px の倍数で、3段階。大きなまとまりの間 32px、まとまりの中 12〜16px、項目の中 4〜8px。
- **書体**: 見出し Shippori Antique（明朝系）または Noto Sans JP の太字、本文 Noto Sans JP（400、500）。Google Fonts から読み込む（スライスで約 100 個のスタイルシートになる。自分のサイトから配る案がある）。
- **フォーカス**: フォーカスの輪郭は、システムで唯一の線。
- 動き: `prefers-reduced-motion` で、0ms に。

## 5. いまの部品（実際に使っているもの）

画面: トップ（検索、分野とタグの絞り込み、順位の行）、作品ページ（左に概要、右に書く場所とレビュー）、作品の編集、自分のレビュー、ログイン、アカウント（パスキー、復旧コード）、復旧、お問い合わせ、規約・プライバシー、管理（作品、通報、受信箱）。

CSS のクラス（`src/lib/styles/app.css`）: `.page` `.header` `.hero` `.layout` `.main` `.panel`（`.flush`）`.card` `.region` `.btn`（`.quiet` `.small`）`.tag`（`.pos` `.neg` `.mix`）`.input` `.field` `.choice` `.check` `.banner`（`.error` `.success` `.warning`）`.dist`（`.hero` `.row`）`.tagrow` `.months` `.rank` `.reviews` `.reading` `.review__meta` `.footer` `.prose` `.code` `.compose`。トースト、ダイアログ、ラジオ、チェックボックスは、ui-sdk の部品（`data-slot` で装飾）。コンポーネント（`src/lib/components/`）: `Dist` `Direction` `Header` `Footer` `Meta` `RecoveryCode`。

トークン（`src/lib/styles/tokens.css`）: 色（`--bg` `--surface` `--text` `--text-muted` `--link` `--tag-*` `--cta-*` `--sentiment-1/3/5-*` `--status-*` `--neon` `--surface-deep`）、文字（`--font-*` `--fs-*` `--lh-*` `--ls-*`）、余白（`--space-*`）、角（`--radius-*`）、影（`--shadow-*`）。ライトとダークは、`prefers-color-scheme`。

## 6. 試しの案

`experiments/design-trials/mono.css`（灰色と白黒に、差し色1色。`data-accent` で切り替え）。比較の画像は、2026-11-19 のセッションで、ユーザーに送った。わかったこと: 差し色は、作品ページではほとんど出ない（出る場所を、意図して決める必要がある）。赤・ピンクは、否定の赤の棒と近く、シアンは、肯定の青緑と近い（オレンジが、ぶつからない。見た目の判断）。灰色と黒の編集的な見た目は、流行でもあり、「独自」とは限らない。製品らしさは、配色より、「理由を並べて見せる」見せ方と動きから出す。

## 7. 成果物と、戻し方

- 成果物: トークン（色、文字、余白、角、影。ライトとダーク）、部品の見本（上の一覧のうち、公開の画面で使うもの）、使い方の決まり（短い文章）。
- **正は、リポジトリの `tokens.css`。** 別の場所に作る見本は、そこから作る（二重にしない）。変数の名前は、いまの `tokens.css` に合わせる（変えるなら、対応表を付ける）。
- 反映は、コードのあるセッションで行う（`tokens.css` を入れ替え、実画面とブラウザの通し（`npm run e2e`、`npm run e2e:passkey`）で確かめる）。公開の画面を先に、管理画面は後。
- 確認の方法: 実画面（トップ、作品ページ、ライトとダーク、幅 390px と 1100px）のスクリーンショットで比べる。`experiments/design-trials/` のやり方（スタイルを上書きして撮る）が使える。
