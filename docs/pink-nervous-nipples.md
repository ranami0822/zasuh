## 1. 概要

自分をそのまま出すメディアの総集。【今回】

- 痛い・不十分・恥ずかしい・個人情報が混ざる・感情的、といった理由で、メモには書いても公開しない考えがある。X に書くものでもない気がする。【過去チャット 10/28】
- 痛々しい本音をそのまま書いて共有できる、ブログ的な Twitter と、書くための最速の PWA エディタを作る。【今回】

## 2. 考え方：匿名の側に立つ理由【今回】

- X のように自己が見える（プロフィールがある）と、どんなに偏った意見でも、意見として不快感や疑問を抱く。
- 匿名掲示板だと、「やばい人が大声を上げている」ことがそのまま分かるので、無視できる。
- 粉飾をなくした匿名のほうが、実際の社会を一般にはよく映すかもしれない。

## 3. 書く側：PWA エディタ

目標: **高速で快適。シンプルに、気軽にたくさん書ける。**【今回】

- PWA として開いたら、そこがもうタイトルと本文を書く場所。一覧ではない。
- 特定のサイトにすぐ upload できる（対象サイトは未決）。
- プレビューは最初から（モードを分けない）。
- Markdown の記法を意識させない。スニペットと、横にスクロールできる細いバー状の部分から、装飾を選ぶ。
- オフラインでも開き、入力しながらローカルに即保存する。公開は後から非同期にする。【今回・提案】
- 「下書き / 限定公開 / 公開」の3段階にして、公開には一手間かける。【今回・提案】

## 4. 場の設計

- 吐き出しの場は、議論の場（DialOD）とは別の空間にする。アカウントは同じでも、空間ごとに仮名にして、互いに紐づかないようにする。【過去チャット・メモ】
- 運営側からも紐づけが見えにくいように、ハッシュ化した仮名を使い、紐づけ表を持たない。【過去チャット】
- 反応や意見は付けられるが、書いた人の地位は変わらない。【過去チャット・メモ】
- Clef で投稿を軸ごとに評価する（個人情報、イタイ、革新的、後悔、感情的、実用的）。ただし順位にはしたくない。【過去チャット・メモ】

### 4.1 決定（2026-11-15、本人）【今回】

反応と返信:

- 反応は置く（反応が全くないと、公開する意味がないため）。いいねを置く。
- 返信は**双方向**。書いた人は、返信を**非表示にできる**。
- **いいねは公開**。**フォロワーはいるが、数は他人に見せない**。数は本人だけが分かる。

匿名と、匿名を外す仕組み:

- 全員匿名が基本。
- 投稿ごとに**トグル**（「共感されたら名乗る」）を持つ。いつでも変更でき、閾値に届く前なら取り消せる。
- 閾値は**いいねの数**。初期値は 20 前後。
- 水増しの対策: 1人1回まで。新しいアカウントのいいねは数えない。いいね以外の方法でもよい。フォローについても、適当に登録して利益を得られない形にしたい。
- 運営が紐づけ表を持たない前提で、名乗る操作は、書いた人自身の署名（passkey）で行う。
- 名乗ると**プロフィール**が出る。プロフィールでは、本人が公開してよいとした昔の投稿や小説が見られる。
- 公開された後も、**匿名に戻せる**。ただし、すでに見られたものや写されたものは取り消せないので、その旨を示す必要がある（私の注意）。
- ねらい: 痛々しいことを勝手に表現でき、共感されたときだけ、それを自分のものにできる。

範囲:

- 小説は**別の場**に置く。
- 「コミュニティ」は、一旦なし。（「いったなし」を、一旦なしと読んだ。）
- Zasuh とは**データを共有しない**。書いた文章を、レビューの素材にもしない。

同じチャットでの AI の提案（採用したかは未確認）【提案・未確認】:

- いいねやフォロワーをなくし、未完成や乱文を前提にする。
- 個人情報は投稿前に検知し、内容には口を出さない。
- 返信は任意か一方向にし、古い投稿は沈むか、自分で消せるようにする。
- 軸の使い分け: 個人情報は投稿前の関門、後悔と感情は「一晩置く」きっかけ、イタイ・革新・実用は順位ではなく閲覧の切り口にする。
- 反応は人ではなく投稿に付け、「共感 / 別の見方 / 自分も似たこと考えた」のように種類で返す。
- 議論の場への昇格は、本人が望んだものだけを手動で行う。
- 作る順番は、吐き出しの場、議論の場、AI 小説、コミュニティの順。
