# GTA6 発売日（2026-11-19）の準備

状態: 2026-11-18 に用意した。コードの変更は、トップの見せ方・共有用の画像・CSP・バックアップ。**本番への反映（デプロイ、作品の登録）は、ユーザーの確認のあと。**

## 当日にやること（この順番）

1. **デプロイ**: `npm test && npm run check` が通ることを確かめ、`npm run deploy`。マイグレーションの追加はないので、`db:migrate:remote` は要らない。
2. **作品を登録**（`/admin`）: 下の「登録する内容」。タグは、登録したあとの作品の編集画面で選ぶ。
3. **確かめる**: トップに、その作品が「いま集めている作品」として出る。自分で1件投稿して、1分以内にタグと向きが付く。共有（Xで共有）の URL を、SNS の確認ツールか、実際の投稿の下書きで見て、画像が出る。
4. **告知**。そのあとは、「見ること」の節。

## 登録する内容

| 項目 | 値 |
| --- | --- |
| URL 用の名前（slug） | `gta6` |
| 名前 | `Grand Theft Auto VI` |
| 分野 | ゲーム |
| リンク | 公式サイトの URL（**確認してから入れる。空でもよい**） |
| 紹介文 | Rockstar Games のオープンワールド作品。（500字まで。事実だけ。評価の言葉は入れない） |
| 追加のタグ | `game/story`（物語）、`game/graphics`（見た目）、`game/multiplayer`（マルチプレイ） |

- トップの「いま集めている作品」は、**直近7日の投稿がいちばん多い作品**（なければ、いちばん新しく登録した作品）。登録した直後は、そのまま GTA6 が出る。ほかの作品に切り替えたいときは、作品の「非表示」ではなく、その作品に投稿が集まるのを待つ（手動の固定はない）。
- 追加のタグを増やすと、1件の読み取りが重くなる（下）。ここでは3つに絞った。`game/localization`（日本語対応）と `game/updates`（更新・運営）は、発売直後は書く人が少ないので外した。
- 追加のタグは、正解付きのデータでは確かめていない（確かめたのは、分野の4つだけ）。順位は、分野のタグだけで決まる（12.7）。

## 容量の見積もり（出典: `docs/mvp-design.md` の12.1、第5・6弾の実測から計算）

| 構成 | 1件の読み取り | 無料枠（1日 10,000 neurons）で読める件数 |
| --- | --- | --- |
| 分野のタグ4つ | 約 2,300 トークン、約 7.9 neurons | 約 1,270 件 |
| 分野4つ + 追加3つ（上の登録） | 約 3,860 トークン、約 13.3 neurons | **約 750 件** |
| 分野4つ + 追加5つ | 約 4,900 トークン、約 16.9 neurons | 約 590 件 |

- 無料枠を超えると、読み取りが失敗する（429）。レビューは保存され、表示もされるが、**集計と順位に入るのが、枠が戻る（00:00 UTC = 日本時間 9:00）まで遅れる**。毎分の定期実行が、読み直す。
- 有料プランなら、超過は 1,000 neurons あたり $0.011。5,000 件で約 66,500 neurons、約 $0.7。
- **Workers の無料プランは、1回の呼び出しの CPU 時間が 10 ms。** 投稿時の「文面がほぼ同じか」の比較（最大500件）は、手元で測ると、500件で 16〜135 ms かかる（本文が 150〜1,500 字のとき）。**レビューが数百件を超えた作品では、無料プランだと、投稿が CPU の上限で失敗するおそれがある。** 本番のプランは、API から確かめられなかった。**まだ無料プランなら、発売前に、Workers の有料プラン（月 $5）にする**のを勧める。有料にすれば、この点と、上の AI の枠の心配が、ほぼなくなる。
- 投稿の上限（端末ごとに24時間で5件、送信元ごとに1日10件）は、同じ回線（学校、会社）から多数が書くと、先に当たる。当日に、お問い合わせが来たら、ここを疑う。

## 見ること（当日）

- Workers のログ（`observability` は有効）: `sweep` と、読み取りの失敗（429 が続いていないか）。
- `/admin`: 読めていないレビューの数、失敗が続いているレビューの数。受信箱の未対応。通報。
- 荒らし: 発売直後は、まだ遊んでいない人の投稿や、組織的な投稿が混ざりうる。ログインがなく、1人1件を保証できない（設計上の限界）。同じ文面は集計に数えないが、言い換えは見つけられない（12.5）。通報が増えたら、`/admin/reports` で非表示にする。
- バックアップ: 発売の前と、翌日に、`npm run db:backup`（手元の `backups/` に書き出す。git には入れない）。

## この準備で変えたこと

- トップ: 「いま集めている作品」の大きな枠、しくみの3段（書く → 読む → 分布）。
- 共有: OGP 画像（`static/og.png`）、`twitter:card` を大きい画像に。作品ページに「Xで共有」。
- ファビコンを、Svelte の初期のものから、Zasuh のものに。
- CSP（`content-security-policy`）を付けた。ローカルで、ブラウザの通し（管理、投稿、編集、通報）が、コンソールのエラーなしで通ることを確かめた。**本番では、デプロイ後に、書体（Google Fonts）が読み込まれていること、投稿のダイアログが開くことを、目で確かめる。**
- バックアップの手順（`npm run db:backup`）。本番に対して、一度実行して、書き出せることを確かめた。
