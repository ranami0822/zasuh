# pnn エディタ 設計（初版）

対象: `pnn/`（Zasuh とは独立）。範囲は、**書く側の PWA エディタ**まで。公開の場（フィード、いいね、匿名を外す仕組み）は、このあとの段階。
前提: `docs/pink-nervous-nipples.md`（要件）、`docs/pnn-design-system.md`（見た目と動き）。

## 1. 要件

機能:

1. 開いたらすぐ書ける。一覧が先ではない。画面の主役はタイトルと本文。
2. プレビューは分けない。書いた記法が、その場で整形されて見える。
3. 記法を意識させない。スニペットと、横にスクロールできる細い装飾バーから選ぶ。
4. 入力しながら、ローカルに即保存する。オフラインでも開く。
5. 状態は「下書き / 限定公開 / 公開」。公開には一手間かける。公開は、あとから非同期に行う。
6. 複数の文書を持てる（小説の章にもなる）。切り替えは副次的。

非機能:

- 起動と入力が速い（体感で遅れがない。日本語の変換中に崩れない）。
- 保存の取りこぼしがない（タブを閉じる、電池切れの直前でも）。
- 小さい初回読み込み。フォントは使う文字の塊だけ（`docs/pnn-design-system.md` §4）。
- 1人で作る。無料枠の Cloudflare で動く。

制約: SvelteKit（Svelte 5）、Cloudflare Workers。UI は、ピクセルの書体、pill の部品、直角のダイアログ、線なし（デザインシステムに従う）。

## 2. 全体

```
┌────────────── ブラウザ（PWA） ───────────────┐
│  Svelte 画面                                  │
│   ├ タイトル欄                                │
│   ├ 本文（CodeMirror 6 + 整形の装飾）         │
│   ├ 装飾バー / スニペット（横スクロール）      │
│   └ 状態の pill、文書の切り替え               │
│        │ 変更                                 │
│  保存層（debounce 250ms + 閉じる前に即時）    │
│        ▼                                      │
│  IndexedDB（文書、公開の待ち行列）            │
│  Service Worker（アプリ本体と主要フォント）    │
└──────────────┬────────────────────────────────┘
               │ 公開の待ち行列だけ（後の段階。オンライン時）
               ▼
        Cloudflare Workers + D1（後の段階）
```

この段階で作るのは、上の枠のうち、ブラウザ側のすべてと、静的配信まで。サーバー側（公開 API）は、状態の持ち方だけを先に決めておき、作らない。

## 3. 主な決定とトレードオフ

| 決定 | 理由 | 引き換えに失うもの |
| --- | --- | --- |
| 本文の編集は **CodeMirror 6**。保存するのは Markdown の文字列 | 日本語の IME（変換中の文字）の扱いが成熟している。「その場で整形」は、装飾（記号を隠し、見た目を付ける）で実現でき、文書は素の文字列のまま | 初回の転送が増える（数十 KB の圧縮後）。contenteditable の自作や ProseMirror のような、構造を持つ文書より、表現は限られる |
| 保存は **IndexedDB**（localStorage ではない） | 容量、非同期、複数文書、バイナリ（将来の画像）に向く | API が重い。薄い自前の層で包む |
| 保存の契機は、入力ごとに **250ms の debounce** と、`visibilitychange` / `pagehide` での**即時の書き出し** | 入力の遅れを避けつつ、閉じる直前の取りこぼしを減らす | `pagehide` の書き出しは、ブラウザが完了を保証しない。最悪で、最後の約 250ms の入力を失う（見直す点） |
| 文書の主キーは、端末で作る **UUID** | オフラインで作ってから、あとで公開できる（サーバーの採番を待たない） | 同じ文書を複数端末で編集すると衝突する。この段階では、1端末が前提 |
| 状態は `draft` / `limited` / `public`。**公開は、2段階の操作**（確認の後に、待ち行列へ） | 要件「公開は一手間」。オフラインでも押せる（待ち行列に入る） | サーバーが無いうちは、`public` は「公開予約」止まり |
| オフラインは、SvelteKit の **service worker**。アプリ本体と主要フォントを先に取り込み、重いフォントは使った時点でキャッシュ | 初回の転送を抑える。珍しい文字は、オンラインなら出る | 重いフォント（1.4 MB）を、オフラインで初めて使う文字には使えない（システムのフォントに落ちる） |
| 本文の既定の書体は UnifontEX。**16 の倍数のサイズ**（16 / 32） | ピクセルの書体をくっきり出すため | 長文の読みやすさは、未検証（`docs/pnn-design-system.md` §5）。小説の場で見直す |

## 4. データモデル

```ts
type Status = 'draft' | 'limited' | 'public';

interface Doc {
  id: string;            // UUID
  title: string;
  body: string;          // Markdown
  status: Status;
  createdAt: number;     // ms
  updatedAt: number;     // ms
  publish?: { requestedAt: number; status: 'queued' | 'sent' | 'failed' }; // 後の段階
}
```

- 保存先: IndexedDB の `docs` ストア（キー `id`、`updatedAt` の索引）、`meta` ストア（最後に開いた文書 など）。
- 「最後に開いた文書」を開く。無ければ、空の文書を作る（一覧を先に出さない）。
- 空の文書（題も本文も空）は、離れるときに捨てる（ゴミを残さない）。

## 5. 画面

- 最上段: 状態の pill（下書き / 限定 / 公開）、文書の切り替え（「いままで」）、新規（＋）、ダークとライト。いずれも、小さく。
- タイトル: 32px。プレースホルダは出さず、カーソルだけ（説明しない）。
- 本文: 16px。見出し、太字、傾き、取り消し、引用、箇条、区切り線は、その場で整形。記号は、カーソルがその行にあるときだけ見える。
- 下: 装飾バー（pill が横に並び、スクロールできる。スクロールバーは出さない）。先頭にスニペット（`「」`、`……`、日付、`♡` など）。押すと、触ったときの動き（`docs/pnn-design-system.md` §6）。
- 文書の切り替え: 直角のダイアログ（面の色の差で区切る。線は使わない）。

## 6. 信頼性

- 保存に失敗したら、画面の隅に小さく知らせる（文言ではなく、状態の点の色で）。入力はそのまま続けられる。
- 保存と読み込みは、1つの層に閉じる（`src/lib/store.ts`）。テストでは、メモリ版に差し替える。
- 壊れたデータ（読めない文書）は、消さずに、読み出しだけ飛ばす。

## 7. テスト

- 保存層: 保存、更新、並び、空の文書の破棄、debounce と即時の書き出し（疑似タイマー）。
- 装飾の命令（太字、見出し、引用、箇条、区切り）: 選択あり・なし、解除、複数行。
- ブラウザの通し確認（Playwright）: 入力 → 再読み込みで残る、オフラインで開く、装飾バーの操作、日本語の変換中に崩れない（IME は自動操作で完全には再現できないので、手で確かめる項目として残す）。

## 8. 範囲外（次の段階）と、見直す点

範囲外: 公開 API と D1、フィード、いいねと保存、匿名を外す仕組み、passkey、小説の場、作業共有スペース、水色のマスクの模様。

規模が大きくなったら見直す:

1. 複数端末での編集（衝突の解決、同期）。
2. 本文の表現（脚注、ルビ、画像）。ルビは、日本語の小説で必要になる見込み。記法の選択は、未決。
3. 長い文書での、装飾の計算コスト（CodeMirror は、表示範囲だけを計算する）。
4. 重いフォントのキャッシュの方針（オフラインで初めて使う文字）。
5. `pagehide` での保存の取りこぼし（実測してから）。
