# 実験: Clef は「言及なし」を推測せずに選べるか

## 目的

設計の根幹である「書かれていない観点を推測しない」が、Workers AI の Clef（日本語）で成り立つかを確かめる。

## 実施の注意

- root で実行しない。専用の非 root ユーザーか、使い捨てのディレクトリで行う。
- 認証情報は環境変数 `CLOUDFLARE_ACCOUNT_ID` と `CLOUDFLARE_API_TOKEN` から読む。値を出力・保存・コミットしない。
- 呼び出しの書式は、Clef の公式ドキュメント（https://developers.cloudflare.com/workers-ai/models/clef）で確認してから書く。推測で書かない。

## 手順

1. `samples.json` の10件のレビューについて、4観点（gameplay, music, comfort, price）を質問にする。
   - 各観点を `choice`（肯定 / 否定 / 混在 / 言及なし）で聞く。
   - 各観点について、`noul`（その観点への言及があるか）も別の質問で聞き、結果を比べる。
2. `clef` と `clef-flash` の両方で行う。
3. 各回答について、選択肢ごとの確率の生の出力と、所要時間を記録する。

## 判定基準（案）

- 正解が「言及なし」の観点で、「言及なし」が最も高い確率で選ばれた割合。特に、サンプル6・10（抽象的、観点が特定できない）での挙動。
- 正解が「言及なし」以外の観点で、「言及なし」と誤る割合。
- 確率の高さと正誤の関係（確率が低い答えを採用しない閾値が引けるか）。
- `noul` と `choice` の「言及なし」の結果の一致度。
- Clef と Clef-flash の差、レイテンシ。

## 結果

実施日: 2026-11-14。`run.py` で実行し、生の出力は `results.json`、集計は `analyze.py`。

### 実施条件

- 非 root の専用ユーザーで実行。認証は環境変数のみ（値は保存していない。`results.json` に混入がないことを確認済み）。
- 書式は公式ドキュメントで確認した。`POST /accounts/{id}/ai/run/@cf/cloudflare/clef`、本文は `{model, state, questions}`。`state` にレビュー本文、`questions` に質問。`choice` は `criteria` に選択肢、出力は `answers.<id>.probabilities`。`noul` の出力は `noul`（「はい」の確率）。
- **clef-flash は `@cf/cloudflare/clef-flash` のエンドポイントで呼んだ。** ドキュメントは本文の `model` に `"clef-flash"` を許すと書いているが、`@cf/cloudflare/clef` に `model: "clef-flash"` を送ると 422（`Unsupported model 'clef-flash'. Use 'clef'.`）になった。clef-flash 専用ページはドキュメントに見当たらず、エンドポイント名は `model` 欄の説明から推測して試し、動いた。
- 1 問 1 リクエスト（質問をまとめない）。10件 × 4観点 × {choice, noul} × 2モデル = 160 リクエスト。すべて 200。各1回のみ（再現性、同じ入力で確率が揺れるかは未確認）。
- 質問文・選択肢の説明は `run.py` にある。選択肢には「書かれていないことを推測で補わない」と書いた。この文言で結果が変わるかは試していない。
- 所要時間は、コンテナから逐次呼んだときのクライアント側の往復時間（ネットワーク込み）。

### 結果（各モデル 40 回答 = 10件 × 4観点）

| 指標 | clef | clef-flash |
|---|---|---|
| 正解が「言及なし」(27) で、「言及なし」が最高確率 | 26/27 | 25/27 |
| 正解が「言及なし」以外 (13) で、「言及なし」と誤る | 0/13 | 0/13 |
| choice の正解率 | 36/40 | 33/40 |
| noul 単独の正解率（0.5 で二値化） | 39/40 | 39/40 |
| noul と choice の「言及なし」判定の一致 | 38/40 | 39/40 |
| choice の所要時間（平均 / 中央 / 最大） | 0.43 / 0.39 / 1.05 秒 | 0.33 / 0.30 / 0.61 秒 |
| noul の所要時間（平均 / 中央 / 最大） | 0.37 / 0.37 / 0.56 秒 | 0.35 / 0.32 / 0.62 秒 |

- **誤りはすべて「混在」への誤答**（clef 4件、clef-flash 7件）。「言及なし」と誤った例も、「言及なし」を取り逃した例も choice にはない。誤りの多くは gameplay 観点（clef は4件全部）。
- サンプル6（「神ゲー。」）は、両モデルとも4観点すべて「言及なし」が最高確率。「言及なし」の確率は clef 0.82〜0.97、clef-flash 0.69〜0.93。noul は両モデルとも 0.02〜0.09 で、言及なしと判断。
- サンプル10（「前作より良くなった点も悪くなった点もある。」）は、music・comfort・price は両モデルとも「言及なし」（clef 0.79〜0.97、clef-flash 0.89〜0.96）。**gameplay は両モデルとも「混在」と答えた**（clef 0.795、clef-flash 0.690。正解は「言及なし」）。この観点は人の正解を「言及なし」としたが、「前作より」の比較をゲーム内容への評価と読めばモデルの答えも筋が通り、正解の付け方自体が曖昧かもしれない。一方 noul は clef 0.157、clef-flash 0.076 で「言及なし」側だった。
- **確率と正誤**: choice の最高確率が 0.9 以上の回答は、clef で 23/23、clef-flash で 17/17 が正解。0.9 未満では clef 17件中13件、clef-flash 23件中16件が正解。誤りの最高確率は clef 0.53〜0.83、clef-flash 0.48〜0.88。0.9 を閾値にすれば、採用した回答に誤りは入らなかったが、採用できるのは clef で 23/40、clef-flash で 17/40 に減る。件数が少ないので、0.9 という値が一般に通用するとはいえない。
- **noul と choice の食い違い**（clef 2件、clef-flash 1件）:
  - clef: サンプル8 gameplay（正解は肯定。noul 0.364 で「言及なし」側、choice は混在）、サンプル10 gameplay（noul 0.157、choice は混在）。
  - clef-flash: サンプル10 gameplay（noul 0.076、choice は混在）。
  - noul の誤りは、clef がサンプル8 gameplay（0.364）、clef-flash がサンプル3 gameplay（正解は言及なしだが noul 0.74。「値段相応に遊べた」を内容への言及と読んだ可能性がある）。

### 所見と限界

- 「言及なしを推測で埋めない」という点では、この10件では両モデルとも期待どおりだった。ただし件数が少なく、各1回のみなので、傾向の確認にとどまる。
- 実際に問題になるのは「混在」への寄りで、特に「肯定と否定が両方ある」ように読める文（サンプル1・8・9）と、観点が曖昧な文（サンプル10）。
- サンプル10 gameplay では、両モデルとも choice は「混在」、noul は「言及なし」側（0.157 / 0.076）と食い違い、noul の方が人の正解と合った。ただし1サンプルの1観点だけの話で、noul 側にも別の誤りがある（上記）。
- clef と clef-flash の差: 正解率は clef が3件多いが、件数が少ないため有意な差とは言えない。clef-flash の方が少し速い（choice で平均 0.33 秒 vs 0.43 秒）が、1回ずつの計測。
- 未確認: 同一入力での確率の揺れ、質問文の言い換えへの頑健性、10件以外のレビュー、長文のレビュー、複数質問を1リクエストにまとめたときの結果の変化とレイテンシ。

# 第2弾（仕様）

第1弾の結果を受けて、次の3点を確かめる。

## 目的

1. **同時に聞いて食い違いを見る方式**: 同じ観点について `choice`（向き）と `noul`（言及の有無）を同じリクエストで聞き、食い違い（`noul` は言及なし側なのに `choice` は言及あり、またはその逆）を「要確認」の印にできるか。
2. **質問文の言い換えへの頑健性**: 質問文と選択肢の説明を言い換えたとき、答えが変わるか。
3. **同一入力での揺れ**: 同じリクエストを複数回送ったとき、確率が変わるか。（発表ブログの説明では、Clef は文章を生成せず1回の処理で採点する方式なので、揺れは小さい見込み。未確認。）

## 入力

- 第1弾の10件（`samples.json`）+ 第2弾の24件（`samples2.json`）= 34件。観点は同じ4つ。
- `samples2.json` の `ambiguous: true` は、正解の付け方に揺れがあるもの。主集計から外して、別に報告する。第1弾のサンプル10も同様に扱う。
- 正解ラベルは Claude が付けたもので、人の確認は未実施。結果を見るときは、誤りと判定された例のラベル自体が妥当かも確認する。

## 手順

実施の注意は第1弾と同じ（root で実行しない、認証情報を出力・保存・コミットしない、書式は公式ドキュメントで確認する）。

- **A. 揺れ**: 第1弾の10件 × 4観点 × {choice, noul} を、同一内容で3回ずつ送る（Clef のみ）。確率の差の最大値を報告する。
- **B. 同時に聞く**: 34件について、4観点 × {choice, noul} = 8問を1リクエストにまとめて送る（Clef と Clef-flash）。第1弾と同じ質問文で、1問ずつ送った場合と比べる。応答時間も記録する。
- **C. 言い換え**: 質問文と選択肢の説明を、意味を変えずに2通り作る（V1: 短い言い方、V2: 別の言い回し）。V0（第1弾と同じ）と合わせて3通りで、34件に対して B の方式で送る。V1・V2 の文面は結果に残す。
- **D. 食い違いの印**: B の結果で、`noul` が 0.5 を境に言及なし側で `choice` が言及あり（またはその逆）の回答を「食い違い」とする。食い違いの回答が、`choice` の誤りをどれだけ拾えるか（拾った数 / 誤りの総数、食い違いのうち実際に誤りだった割合）を報告する。

## 判定基準（案）

- A: 確率の差の最大値が 0.01 未満なら、揺れは無視できる。
- B: 1問ずつ送った場合と、正解率・「言及なし」の判定が同程度か。応答時間は短くなるか。
- C: 3通りの文面で、`choice` の最高確率の選択肢が変わる回答の割合。
- D: 食い違いの印が、`choice` の誤りの何割を拾えるか。誤検出（正解なのに食い違い）は何件か。
- 全体: 「混在」への寄りが、サンプルを増やしても続くか。
